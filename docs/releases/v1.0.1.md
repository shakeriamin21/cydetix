# Cydetix v1.0.1

Stable `v1.0.1` was published to npm `latest` and finalized as a normal GitHub release by trusted
OIDC release run `35085779583` on 2026-09-16. Its annotated tag targets evidence commit
`e06ba195beeb5c3428e65e3f95049b39afa2891c`. Exact-commit CI run `35084476591`, CodeQL run
`35084476327`, and OpenSSF run `35084476387` succeeded before the tag was authorized.

The annotated `v1.0.0` tag is an immutable failed release attempt. Trusted release run `35063154124`
stopped at current-version release-report validation because the tag targeted the source candidate
without `validation/releases/v1.0.0/validation-report.json`. The publish job was skipped, so no
`1.0.0` npm package or public GitHub release was created and npm `latest` did not move. The `v1.0.1`
recovery did not alter or repair that tag.

## Recovery scope

- Advanced package, CLI, plugin, documentation, and release metadata to `1.0.1`.
- Registered the exact immutable `v1.0.0` tag object, peeled target, failed trusted run, and
  no-publication disposition in release-history validation.
- Used the existing two-commit contract: one source commit `S`, followed by one evidence commit `E`
  that changed only `validation/releases/v1.0.1/validation-report.json`.
- Preserved the audited V1 security product, exact three-tool MCP surface, package-export boundary,
  and trusted stable-release workflow without adding detection rules, changing proof meanings, or
  expanding remediation authority.

## Limitations retained

- `UNKNOWN` and `TRUNCATED` remain honest non-proof outcomes. Unsupported, ambiguous, incomplete,
  resource-bounded, or failed analysis never silently becomes `PROVEN_SECURE`.
- Parser, language, framework, call-graph, dependency, resource, and rule coverage remains bounded
  to documented supported patterns. Whole-program and deployed-runtime proof are not claimed.
- External corpus ground truth remains incomplete and selectively adjudicated. No corpus-wide
  recall, completeness, generic accuracy, or zero-false-positive/negative claim is made.
- Resolved dependency inventory remains limited to npm `package-lock` v2/v3. Inventory presence does
  not prove vulnerable-function reachability; PyPI and SPDX inventory are not implemented.
- Secret analysis remains passive, redacted, and intentionally narrow. Live credential validity,
  rotation, revocation, monitoring, and history remediation are not proven.
- SAFE remediation authority remains exactly one bounded session-cookie adapter. Dependency,
  workflow, authentication, authorization, credential-response, and architectural changes require
  review or architectural work.
- Container isolation depends on the trusted Docker daemon, kernel/hypervisor, immutable image, and
  declared runtime controls. The writable ephemeral workspace has no independent byte quota, and
  supported copy/build inputs remain bounded.
- Host UI selection, implicit tool invocation, marketplace behavior, and adapter compatibility are
  best effort. The deterministic CLI/MCP engine remains host-independent.
- Performance evidence remains environment-specific and descriptive. No cross-host performance SLO
  or universal large-repository performance guarantee is claimed.

## Publication evidence and historical schema

The immutable report uses release-validation schema `1.2.0`, whose ready label was
`PUBLIC_ALPHA_READY_WITH_LIMITATIONS` for every release channel. That literal historical value is
preserved and is not silently reinterpreted or rewritten. The stable publication fact comes from the
immutable annotated tag, successful trusted workflow, GitHub Release, and npm registry state.
Forward reports use channel-aware schema `1.3.0`.

The successful package and GitHub release do not broaden the audited support envelope or convert
these limitations into proof of completeness, vulnerability freedom, or production fitness.
