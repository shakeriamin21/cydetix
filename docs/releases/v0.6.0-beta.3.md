# Cydetix v0.6.0-beta.3

Cydetix `v0.6.0-beta.3` is the smallest recovery candidate after the immutable failed Beta.2
attempt. It adds the versioned release-validation report required by the existing release-evidence
contract. It does not change product behavior, detection rules, proof semantics, remediation
authority, sandbox security, dependencies, architecture, or the three-tool MCP public surface.

## Release-evidence recovery

The Beta.3 source preparation is committed first as source commit `S`. The complete local evidence
pipeline is then executed against that clean commit. The resulting report is written to
`validation/releases/v0.6.0-beta.3/validation-report.json` and committed alone as evidence commit
`E`, whose direct parent is `S`. The report identifies `S`; any future annotated Beta.3 tag must
target `E`. This follows the existing contract without weakening or special-casing validation.

## Beta.2 immutable failed-release history

`v0.6.0-beta.2` is immutable. Annotated tag object `a76d297b9749aff247ce980310441d1b058f1644`
targets `e4dbda8b15620e99827b056b92b51ce68a4c60e8`. Trusted release run `34937375125` passed the
exact-commit CI, CodeQL, OpenSSF, history, independent Gitleaks, npm audit, complete test, mandatory
Docker, package, and packed-install gates before release validation failed closed because
`validation/releases/v0.6.0-beta.2/validation-report.json` was absent. The publish job was skipped:
no npm package was published and no public GitHub Beta.2 release was created.

The Beta.2 tag must not be deleted, moved, repointed, recreated, or force-updated.

## Existing scope and limitations

Beta.3 carries forward Beta.2 product behavior and documented limitations. `UNKNOWN` and `TRUNCATED`
remain meaningful; absence of findings under incomplete analysis remains non-proof. The public MCP
contract remains exactly `cydetix_scan`, `cydetix_fix`, and `cydetix_explain`, and the existing
session-cookie transformation remains the only SAFE remediation adapter.

This preparation does not authorize a tag, npm publication, or GitHub release. The final Beta.3
evidence commit must receive exact-SHA CI, CodeQL, and OpenSSF success before an annotated
`v0.6.0-beta.3` tag may be created.
