# Cydetix v0.6.0-alpha.2

**PREPARED ALPHA RELEASE -- NOT PUBLISHED BY THIS CHANGE**

This prerelease aligns the public Cydetix package, CLI, Codex plugin, pinned agent integration, and
release metadata at `0.6.0-alpha.2`. It retains the existing deterministic security engine,
policy-bounded remediation, sandbox controls, structured evidence, and fail-closed release gates. No
security rule family or remediation classification changes in this release preparation.

## Included product experience

- `npx cydetix` and `cydetix` scan the current project with zero mandatory configuration.
- Concise human output preserves richer JSON and SARIF evidence for machine and advanced use.
- `cydetix fix` applies only engine-classified SAFE changes after explicit fix intent, verifies the
  transaction, rescans, and reports residual findings.
- `cydetix setup` detects supported AI coding hosts and installs idempotent, version-pinned
  integrations with the required permission boundary.
- The first-party MCP server exposes only `cydetix_scan`, `cydetix_fix`, and `cydetix_explain`, all
  backed by the same deterministic engine as the CLI.
- The single `cydetix` skill supports semantic selection for relevant security requests while
  excluding unrelated coding work.

## Release path

The repository's existing GitHub Actions release workflow is prepared for npm Trusted Publishing
through OIDC. It uses the protected `release` environment, GitHub-hosted runners, exact-commit
hosted CI and OpenSSF Scorecard checks, security/sandbox/OSV/audit gates, Cydetix artifact creation,
and the `alpha` npm dist-tag. This preparation does not prove that the external npm
trusted-publisher setting is configured and does not claim that an alpha.2 OIDC publication has run
or succeeded.

## Security and naming limitations

Cydetix is bounded static analysis, not certification that a project is secure, vulnerability-free,
compliant, or production-ready. Unsupported or inconclusive cases remain UNKNOWN or uncovered as
documented. The existing npm registration does not establish product-name exclusivity or trademark
clearance; neither is claimed.

Read `README.md`, `docs/CLAIMS.md`, `docs/VALIDATION.md`, and `docs/LIMITATIONS.md` before relying
on this alpha in a sensitive workflow.
