# Cydetix v0.6.0-beta.2

Cydetix `v0.6.0-beta.2` is the next release candidate after the immutable failed Beta.1 attempt. It
contains a narrow release-test context correction and no product feature, security rule, remediation
authority, dependency, or architecture change.

## Release-boundary correction

Development validation remains an explicit development-only gate and still rejects either
`CYDETIX_EXPECTED_TAG` or `GITHUB_REF_TYPE=tag`. The development-positive tests now preserve the
parent process environment. In a genuine development checkout they continue to exercise and pass the
development validator; in an actual tag checkout they assert its fail-closed release-context
rejection. They no longer delete the two release selectors and manufacture a development scenario
inside `npm run verify`.

Negative coverage continues to prove that each release selector is rejected independently, that
unexpected or unrecorded historical tags are rejected, and that a conflicting current-version tag is
rejected outside an explicit tag-release context. The `assessReleaseTagIntegrity` implementation is
unchanged.

## Beta.1 immutable failed-release history

`v0.6.0-beta.1` is immutable. Annotated tag object `4aecf7055d2184d18e1dc5da63dd3a6e65e0259d`
targets `9ecc68f54127e5951d7c2a829cdd719b35779809`. Trusted release run `34930694658` failed during
`npm run verify` because development-only positive tests stripped the tag-release environment and
then encountered Beta.1 as an unexpected, conflicting development tag. The publish job was skipped:
no authorized npm publication occurred and no public GitHub Beta.1 release was created.

The tag identity and its versioned validation report are retained in the immutable release-history
registry. Beta.1 must not be deleted, moved, repointed, recreated, or force-updated.

## Existing scope and limitations

Beta.2 carries forward the Beta.1 product behavior, conservative proof semantics, documented
limitations, and Alpha.12 beta-readiness evidence. `UNKNOWN` and `TRUNCATED` remain meaningful;
absence of findings under incomplete analysis remains non-proof. The public MCP contract remains
exactly `cydetix_scan`, `cydetix_fix`, and `cydetix_explain`, and the existing session-cookie
transformation remains the only SAFE remediation adapter.

This preparation metadata does not authorize a tag, npm publication, or GitHub release. The trusted
tag-driven workflow and exact-commit release evidence remain authoritative.
