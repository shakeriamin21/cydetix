# Cydetix v0.6.0-alpha.9

`0.6.0-alpha.9` is a release-recovery version for the Trust Assurance and Batch 1 functionality
already validated in the alpha.8 candidate. It does not add new security rules or change the
validated security semantics.

## Trust Assurance

This release carries forward the Trust Assurance architecture: proof-carrying findings, explicit
analysis completeness, reproducible scan manifests, deterministic catalogue/configuration/
suppression fingerprints, and auditable suppressions. Missing or incomplete evidence remains
explicit and never becomes proof of security.

Remediation authority is bounded by monotonic `maxRemediationClass` ceilings and reason-coded
runtime assessment. `cydetix rules` exposes the admitted rule catalogue and `cydetix trust` exposes
machine-readable runtime trust state. The existing exact session-cookie adapter remains the only
SAFE transformation; every Batch 1 remediation ceiling remains `REVIEW_REQUIRED`.

## Batch 1

The bounded source-propagation-control-sink engine provides high-confidence coverage for supported
SQL injection, OS command injection, path traversal, and SSRF patterns in JavaScript/TypeScript and
Python server contexts. Findings retain deterministic evidence, proof state, reachability,
fingerprints, completeness, and remediation assessment.

External-corpus validation reviewed 19 pinned repositories without executing target code or
installing target dependencies. Across that reviewed corpus, all 11 actionable Batch 1 findings were
manually proof-audited and confirmed, with zero confirmed false positives after correction. Three
uncertain flows remained explicitly `UNKNOWN`. Unsupported cross-file, framework, sink, and
large-graph patterns remain outside the documented proof envelope rather than being reported as
secure.

Current limitations include bounded/truncated analysis on large repositories, incomplete support for
cross-file handler and Python framework flows, and no proof of custom sanitizer or destination
policy semantics. The exact support envelope and evidence are recorded in
`docs/security/RULE_COVERAGE.md`, `RULE_ADMISSION_GATE.md`, `TRUST_MODEL.md`, `PROOF_MODEL.md`,
`SAFE_FIX_ADMISSION.md`, and `ALPHA8_EXTERNAL_CORPUS_VALIDATION.md`.

## Release history

`v0.6.0-alpha.8` was an immutable failed publication attempt. It stopped before registry publication
because release metadata did not contain the required exact changelog heading. No alpha.8 npm
package or public GitHub prerelease was created. The alpha.8 tag remains an immutable record of that
safely stopped attempt.
