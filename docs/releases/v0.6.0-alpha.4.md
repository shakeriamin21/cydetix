# Cydetix v0.6.0-alpha.4

**REPLACEMENT ALPHA CANDIDATE -- NOT PUBLISHED BY THIS CHANGE**

This candidate follows two immutable, unpublished release attempts:

- `v0.6.0-alpha.2` stopped at publication-configuration validation before npm publication.
- `v0.6.0-alpha.3`, fixed at commit `7aa5007332b4f961b2812d739abd638fba6645cf`, stopped in release

## Git-history privacy scope correction

The alpha.3 release checkout correctly fetched complete history, but `scripts/audit-git-history.mjs`
enumerated `git rev-list --all` and collected author metadata with `git log --all`. A fetched
Dependabot branch therefore introduced an unapproved author fingerprint even though its commit was
not an ancestor of the tagged release commit.

Alpha.4 makes history scope explicit and fail-closed:

- `--ref <revision>` resolves the supplied revision to exactly one commit, then audits that commit
  and every reachable ancestor.
- `--all` remains a separate explicit repository-wide maintainer mode.
- Missing, conflicting, malformed, or unresolvable scope input fails closed.
- Approved author-email SHA-256 fingerprints and forbidden local path/name evidence are still
  checked for every commit in scope.
- Sorting and structured scope metadata keep output deterministic and auditable.
- The release workflow passes `refs/tags/${CYDETIX_EXPECTED_TAG}` only after the earlier release
  context gate has verified the annotated tag, package version, checked-out commit, changelog,
  release notes, and clean tree.

An unrelated branch can no longer change approval of a fixed tag. If that branch is merged, its
commits become reachable and fail the same author/path privacy controls. This is not a Dependabot
allowlist and does not ignore any reachable author.

The independent pinned Gitleaks container continues to scan complete Git history. Secret scanning
and author/path privacy auditing remain separate blocking release controls.

## Preserved release security

This change does not alter Cydetix product analysis, canonical repository path handling, symlink
protection, SAFE-only mutation policy, atomic writes or rollback, hardened Docker execution, genuine
Microsoft SARIF Multitool validation, approved maintainer fingerprints, publication identity, or
OIDC publishing design.

The package, CLI, lockfile root, Codex plugin, pinned MCP/skill launchers, tests, validation
metadata, and publication candidate are aligned at `0.6.0-alpha.4`. The npm package remains
`cydetix`, the primary binary remains `cydetix`, the dist-tag remains `alpha`, Trusted Publishing
remains recorded as `CONFIGURED`, private vulnerability reporting remains `ENABLED`, and trademark
clearance remains `NOT_CLAIMED`.

## Verification required before any release action

The candidate must pass formatting, lint, type checking, the full normal suite, focused history
scope regressions, publication validation, release-scoped history enforcement, package dry-run,
genuine SARIF Multitool validation, workflow-security validation, and the separate 13-test hardened
Docker sandbox suite. No local preparation creates a tag, publishes npm, pushes Git, or creates a
GitHub release.

Read `README.md`, `docs/CLAIMS.md`, `docs/VALIDATION.md`, and `docs/LIMITATIONS.md` before relying
on this alpha in a sensitive workflow.
