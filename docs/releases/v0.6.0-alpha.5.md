# Cydetix v0.6.0-alpha.5

**REPLACEMENT ALPHA CANDIDATE -- NOT PUBLISHED BY THIS CHANGE**

This candidate follows three immutable, unpublished release attempts. In particular,
`v0.6.0-alpha.4` remains fixed at commit `a7faa9ae085e553334e196a4cdbe5153fbceb1f9`; it is not
deleted, moved, repointed, or reused.

## Alpha.4 release outcome

Release run `34098600275` successfully completed publication identity, annotated tag/version/commit
consistency, exact hosted CI and OpenSSF Scorecard checks, release-reachable history privacy,
independent full-history secret scanning, npm and OSV advisory gates, the mandatory hardened Docker
sandbox, exact artifact construction, tarball smoke testing, plugin validation, bundle upload,
downloaded checksum verification, build provenance attestation, CycloneDX SBOM attestation, and
creation of a non-public draft GitHub prerelease.

The subsequent npm command received `release-bundle/cydetix-0.6.0-alpha.4.tgz`. Because that
relative package spec did not begin with `./`, npm parsed it as GitHub repository shorthand and ran
`git ls-remote` against a synthesized SSH URL. The command failed before registry or OIDC
authentication. No alpha.4 npm publication occurred. The final GitHub-release step was skipped, so
the draft prerelease remained non-public.

This was not evidence of a Trusted Publishing failure. Trusted Publishing remains recorded as
`CONFIGURED`, but a successful direct npm OIDC publication has not yet been empirically proven.

## Deterministic local-tarball publication boundary

The alpha.5 workflow now:

- enables Bash `nullglob`;
- expands only `release-bundle/*.tgz` into an array;
- fails unless the array contains exactly one tarball;
- quotes the selected array entry and prefixes it with `./`;
- publishes that already verified tarball with `--access public --tag alpha --ignore-scripts`.

Workflow-security validation requires this exact boundary and rejects the former ambiguous package
spec, a relative array entry without `./`, directory publication, omitted lifecycle-script
protection, or weakened tarball cardinality. It does not add a token, change the registry, disable
OIDC or provenance, remove `id-token: write`, or bypass checksum and attestation gates.
