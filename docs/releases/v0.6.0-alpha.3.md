# Cydetix v0.6.0-alpha.3

**REPLACEMENT ALPHA CANDIDATE -- NOT PUBLISHED BY THIS CHANGE**

This release candidate replaces the failed `0.6.0-alpha.2` release attempt. The alpha.2 tag
triggered GitHub Actions, but the workflow stopped at `validate:publication-config` before npm
publication. A registry check on 2026-09-06 confirmed that npm still contains only
`cydetix@0.6.0-alpha.1`.

## Changes from the alpha.2 candidate

- Advanced the npm package, lockfile root, CLI-reported version, Codex plugin manifest, pinned MCP
  and skill fallback commands, tests, and release-candidate metadata to `0.6.0-alpha.3`.
- Recorded the maintainer-provided state that the npm Trusted Publisher and GitHub private
  vulnerability reporting settings have been completed.
- Preserved the existing approved Git-history author-email hashes.
- Retained the exact unscoped `cydetix` package and binary identity, GitHub repository
  `shakeriamin21/cydetix`, protected `release` environment, and `alpha` npm dist-tag.
- Corrected hosted Unix SARIF validation for the script-disabled dependency install: Cydetix now
  proves that the Microsoft SARIF Multitool native path belongs to the matching Microsoft platform
  package before restoring only its missing user execute bit. The verified binary still runs with
  `shell: false`, bounded output, a timeout, and fail-closed exit handling.
- Corrected the hosted Linux sandbox image lookup by passing the same repository-qualified,
  SHA-256-pinned Node reference that the workflow pulls. The capability probe also recognizes only
  Docker's equivalent `null`/empty-array entrypoint and no-new-privileges representations and names
  failed mandatory checks without returning daemon output or host paths.

No security rule, deterministic analysis, report schema, remediation classification, mutation
boundary, sandbox control, or release-workflow architecture was weakened or removed. These changes
repair release validation while retaining the same fail-closed policy.

## Existing product behavior

- `npx cydetix` and `cydetix` scan the current project without mandatory configuration.
- `cydetix fix` applies only engine-classified SAFE changes after explicit fix intent, verifies the
  transaction, rescans, and reports residual findings.
- `cydetix setup` manages version-pinned integrations for supported AI coding hosts.
- The first-party MCP server exposes only `cydetix_scan`, `cydetix_fix`, and `cydetix_explain`, all
  backed by the same deterministic engine as the CLI.

Local preparation produced these results:

- `npm run validate:publication-config` stopped fail-closed because the maintainer has not

- `node scripts/audit-git-history.mjs --enforce` passed for four reviewed commits against the two

- The final exact `npm run verify` passed. Its default test invocation reported 194 passed and 13
  Docker-capability-skipped tests; a separate pinned-image run passed all 13 sandbox integration

- `npm publish --dry-run --tag alpha` passed for `cydetix@0.6.0-alpha.3`: 324 files, 301,026 packed
  bytes, 1,890,368 unpacked bytes, and the `alpha` dist-tag. It did not publish anything.
- `git diff --check` passed.
- The release preview exercised isolated npm-exec and global-prefix installs plus the packed Codex
  plugin and remained `NOT_READY_FOR_PUBLICATION`, as expected for an uncommitted local preview
  without hosted exact-commit CI or Scorecard evidence.

Local Docker Desktop cold-start and load latency caused earlier sandbox attempts to fail closed at
the capability or workload bounds. The final pinned-image run passed 13/13 after warm-up. Outer test
harness deadlines for two multi-operation scenarios were made long enough to contain their existing
individually bounded Docker operations; no Cydetix probe, workload, output, cleanup, or sandbox
control timeout was relaxed. A local dry-run or preview cannot substitute for the release workflow's
hosted exact-commit checks or external publication state.
