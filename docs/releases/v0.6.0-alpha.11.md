# Cydetix v0.6.0-alpha.11 development notes

`0.6.0-alpha.11` is the unpublished Batch 2 development identity. It starts from the immutable
successful `v0.6.0-alpha.10` public baseline and is not a release or publication record. This
mission does not create or push an alpha.11 tag.

## Batch 2 application-security coverage

The candidate adds three bounded production rule families: context-aware cross-site scripting
(`AS-XSS-001`), attacker-influenced open redirect (`AS-REDIRECT-001`), and architecture-aware CSRF
(`AS-CSRF-001`). The rules use deterministic source-propagation-control-sink evidence and retain
route/function context, proof and completeness states, confidence, reachability, rule version,
reproducibility fingerprints, and bounded evidence paths.

XSS differentiates supported HTML body, attribute, script, URL, and raw-HTML contexts. It does not
report ordinary React interpolation or autoescaped Jinja value binding. A recognized escape only
proves security in a compatible context; opaque custom sanitizers produce `UNKNOWN`.

Open redirect requires an attacker-controlled destination reaching a supported framework redirect
API without a proven destination policy. Fixed destinations and narrowly modeled exact host/origin
allowlists are controls. A slash-prefix check is not accepted because protocol-relative values and
parser behavior remain security relevant.

CSRF correlates a supported state-changing route with ambient cookie/session authentication and the
absence of a proven anti-CSRF control. Explicit bearer-only APIs are non-ambient within the
supported model. SameSite-only evidence, unresolved authentication, or opaque middleware produces
`UNKNOWN` instead of a security conclusion.

## Authority and limits

All three rules have a `REVIEW_REQUIRED` maximum remediation class. Alpha.11 adds no SAFE adapter:
Cydetix does not invent HTML context transformations, redirect destination policy, or application
CSRF architecture. Unsupported template engines, opaque wrappers, dynamic routing, arbitrary URL
normalization, browser-specific edge cases, and whole-program middleware/authentication inference
remain outside the proof envelope and are reported as incomplete where the engine has relevant
evidence.

The complete admission evidence, fixture counts, external-corpus review, determinism results,
resource bounds, regression results, and remaining risks are recorded in
`docs/security/ALPHA11_BATCH2_VALIDATION.md` once validation is complete.
